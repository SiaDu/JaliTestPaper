\section{System}

We implemented a Maya-based authoring prototype that separates conversational performance interpretation from animation execution. The participant-facing tool runs in Autodesk Maya 2025 using PySide6, while LLM generation and canonical-plan compilation run in a separate Python backend. The backend stores the shared dyadic proposal as a validated sparse Performance Plan; the Maya authoring surface projects that plan as two character-specific Semantic Performance Tag editors over the same dialogue. Throughout this section, we reserve \textit{Performance Plan} for this canonical backend object and \textit{Semantic Performance Tags} for the participant-facing editable projection. The execution path is deterministic after generation (Figure~\ref{fig:system-overview}).

\subsection{Anchored Conversational Context and Performance Interpretation}

The workflow begins with labeled dyadic dialogue, an optional free-text \textit{Acting Direction}, and two explicit character identities. The Acting Direction may contain scene information, character motivation, relationship context, or performance constraints. Character identities are treated as immutable throughout generation so that speaker order or narrative role cannot cause the two actors to be exchanged.

Before any model call, the system deterministically converts the dialogue into ordered turns and global word anchors (\texttt{w0001}, \texttt{w0002}, \ldots). Each anchor retains its exact source text, speaker, turn identifier, and source position. The LLM therefore selects semantic change points using stable anchor identifiers rather than reproducing dialogue text or estimating character offsets. The same anchor scaffold is subsequently reused for editing and timing resolution.

The current prototype uses \texttt{gpt-5.6-luna} through the OpenAI API with medium reasoning effort and no task-specific training or fine-tuning. A single model call receives the immutable dialogue, anchored dialogue with speaker metadata, optional Acting Direction, character-identity contract, and the executable semantic vocabulary. The prompt requires exactly two sections: an initial state for both characters and a sparse list of semantic beats. The initial state contains each character's visible affect, persistent attention, optional persistent head state, and a concise natural-language acting interpretation. Each later beat belongs to one actor, is anchored to one dialogue word, and contains an acting interpretation together with at least one executable semantic change. Affect, attention, head, and blink remain sparse---only channels that genuinely change are emitted---and acting-only beats are omitted because they have no authorable executable effect in the current prototype.

The interpreter considers speaking and listening behavior independently. A listener reaction may be anchored to the earliest semantically sufficient word in the other character's speech rather than delayed until the end of the turn. At the semantic level, attention distinguishes persistent focus from a temporary brief check. In the LLM-facing Semantic Beat representation, these are expressed as \texttt{focus: TARGET} and \texttt{eye\_action: brief\_check TARGET}, respectively. After validation, persistent focus compiles to an author-facing \texttt{GAZE-*} tag, while a brief check compiles to \texttt{GLANCE-*} and automatically returns to the previously active persistent target. Targets may refer to either interlocutor, another person, a physical object or location, or one of the supported directional aversions. The prompt treats upward or downward aversion as context-dependent acting priors rather than fixed psychological codes.

Executable affect is constrained to the supported JALI Mask vocabulary and an explicit intensity. Head and blink choices similarly use finite executable vocabularies, whereas the \texttt{acting} field remains open natural language. This distinction allows an interpretation such as hesitation, guarded curiosity, or concealed discomfort to remain semantically expressive without requiring every acting description to correspond to a single facial control.

Model output is parsed and validated before it becomes authorable. Invalid affect labels, unsupported head or blink values, unresolved character identities, unknown anchors, malformed attention actions, or duplicate events at one actor's anchor are rejected rather than guessed. The parsed semantic beats are then deterministically compiled into the canonical \texttt{dual\_performance\_plan\_v2}. This plan stores ordered character identities, per-character initial states, per-character sparse event tracks, semantic gaze-target candidates, and provenance. Redundant persistent no-op changes are removed deterministically while the original generated content is retained in provenance.

\subsection{Semantic Performance Tag Authoring}

The Maya interface presents the canonical plan through a readable authoring projection rather than exposing JSON directly (Figure~\ref{fig:interface}). In dual mode, each character has a separate Semantic Performance Tag panel over the same immutable dialogue. Dialogue spoken by the panel character and dialogue heard from the interlocutor are visually distinguished, while semantic tags are rendered separately. This makes speaking and listening behavior visible within the same conversational timeline without merging the two characters' editable state. Following the high-level tagged-control tradition exemplified by S$^3$ \cite{pan2024s3}, we call this author-facing projection the \textit{Semantic Performance Tag} representation. Here, however, the tags are not required as director-authored input: they are projected from the AI-proposed canonical plan and remain editable before deterministic execution.

Initial persistent state appears before the dialogue, while later changes are inserted as compact tags at their anchored locations. The current editable channels are visible affect, gaze/attention, head behavior, and performative blink. For example, changing a persistent gaze tag from one interlocutor to a scene target changes the semantic decision without requiring the animator to edit eye-control curves or a look-at coordinate. Dialogue tokens and punctuation remain immutable; the editor validates that the authored tag projection still corresponds exactly to the canonical dialogue and executable vocabulary before applying an edit. Within that validated vocabulary, a user may change, add, remove, or reposition one or several tag clusters across either character before applying the edited projection; multiple channels may be revised in the same authoring pass.

The interface separates three authoring operations. \textit{Generate Performance Plan} invokes the external backend and loads a new validated plan only after generation succeeds. \textit{Validate Tag} checks the edited Semantic Performance Tag projection without changing the canonical plan. \textit{Apply Tag Edits} writes valid local semantic edits back into the in-memory plan. The original generated acting interpretation associated with each initial state or beat remains available in a read-only \textit{Acting Interpretation by Phrase} view. If a user changes a generated semantic decision, that original interpretation is retained as provenance but is marked stale with respect to the edited tag; user-added semantic changes have no original LLM interpretation. We use this view to communicate the intended acting interpretation, not to expose hidden chain-of-thought.

Animation-specific setup is intentionally kept outside the semantic representation. Character-to-rig mappings, audio files, and semantic-target-to-Maya look-at calibration are configured separately. Look-at calibration is performed separately from semantic authoring. For each required actor--target pair, the animator adjusts the character's gaze while viewing the current Maya shot and captures the resulting look-at pose. The captured pose becomes the execution target for semantic directives such as \texttt{GAZE-B}; the semantic tag itself does not encode a fixed world-space position or eye rotation. Consequently, the same semantic attention decision can be retained while the animator adapts gaze realization to different camera viewpoints, staging arrangements, or rigs. The Semantic Performance Tags can therefore be generated and edited before the user supplies the rig-specific information required for execution.

\subsection{Deterministic Compilation to JALI and Maya}

\textit{Generate Animation} uses the currently edited canonical plan as its source of truth. The execution layer does not ask the LLM to produce timing, frames, rig coordinates, or animation curves. Instead, it resolves semantic anchors against per-character speech alignments and converts each authored change into deterministic runtime artifacts.

For each character, the compiler loads the corresponding WAV file and one word-level alignment file, either a \texttt{words.jsonl} file or a TextGrid \texttt{words} tier. Dialogue word anchors are matched to these alignments. When a beat is attached to the character's own spoken word, its runtime onset is the aligned word start. When a listener beat is triggered by the other character's word, its onset is resolved to the end of the heard word, so that a reaction follows the semantically sufficient cue rather than anticipating it. The compiler then propagates persistent affect, gaze, and head state forward through the sparse event track while keeping temporary glance and blink actions event-local.

The JALI layer provides speech-driven facial animation and executable affect states \cite{edwards2016jali}. For each speaker, the backend compiler constructs an annotated JALI transcript from the resolved affect state over that character's spoken words. Gaze, head, and blink decisions remain in the resolved sparse event representation; Maya-side deterministic applicators subsequently derive and apply their corresponding animation layers.

For gaze execution, we adopt a high-level tagged control abstraction similar to the transcript-level gaze directives used in S$^3$ \cite{pan2024s3}. Persistent focus compiles to a \texttt{GAZE-*} directive, while a temporary brief check compiles to \texttt{GLANCE-*} and returns to the previously active persistent target. Unlike S$^3$, however, these directives are not authored by the animator in the input dialogue: they are deterministically compiled from the edited canonical plan after the AI-proposed semantic attention decisions have been inspected or revised through the Semantic Performance Tags. Character and object targets are resolved through the user-provided Maya mappings or captured look-at calibration; supported directional targets use rig-relative directional offsets.

The backend compiler writes a dual animation manifest together with per-character resolved sparse events, persistent state timelines, and JALI-annotated speaker transcripts. Maya-side deterministic applicators then use the resolved events, calibrated look-at poses, and mapped JALI rigs to construct and apply the corresponding affect, gaze, head, and blink animation layers. This boundary is central to the system design: the LLM proposes \textit{what} the conversational performance means and where semantic changes occur, while deterministic code decides \textit{how} those decisions are aligned, validated, and instantiated as animation.
